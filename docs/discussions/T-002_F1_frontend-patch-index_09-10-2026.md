- **What it changes (plan v18 sections 2 and 8, brief B v10 4.4, 4.5, 5.4, 5.5):** every screen that offers a course now renders the typed rows of the ONE database catalogue, in the database's order, with the database's wording; none keeps its own list. Nothing is rendered or called until `AuthContext.loading` has resolved; a session uses the authenticated reader, no session the public one. A result that breaks the contract (not an array, empty, no Other row, unknown kind, positions out of order, General missing on the picker or present elsewhere) or a failed call is a contract failure and shows a neutral state instead of a guessed list.
  1. **Signup** (`src/pages/auth/Signup.jsx`): the list is `get_course_options_public` (active platform courses, six CMA/CS labels, Other). The old direct reads of `notes` and `flashcards` course text are gone. `Other` is the shared value `__other__`, never sent. If the list cannot be loaded the course field is disabled, a retry link is shown and sign-up is not submitted.
  2. **Profile Settings** (`ProfileSettings.jsx`): the list is `get_course_options('profile')`: the student's own custom course marked "(current)", an inactive platform course marked "(no longer offered)", and a real typed-course input behind Other (same rule as Signup). A typed course that equals a listed course (ignoring case and spacing) is saved as that listed course; after a save the stored value is read back so the form and the course-change check use what the database canonicalised. An over-long saved course is not listed and a notice says why. If the list cannot be loaded the course select is disabled but the other details can still be saved.
  3. **Access form** (`ContentPreviewWall.jsx`): visitor: the public list; signed-in student: `get_course_options('access')` with the current course preselected (including an inactive or custom one) until another is chosen; a typed course follows the same rule; an over-long saved course leaves the field empty with the notice. Not submittable while the list is unavailable.
  4. **Study-log picker** (`StudyTimerWidget.jsx`, new `StudyLogCoursePicker.jsx`, `StudyTimerContext.jsx`): above the category buttons, a Course row (current course preselected, a change list: other active platform courses, earlier custom labels, General, Other) and an optional Subject row (the subject list of the chosen course; Skip; the last subject used for a course is remembered on this device only). `confirmCategory(category, classification)` now inserts the classification columns with the category: platform (`discipline_id`, optional `subject_id`), custom (`custom_course_label`, optional `custom_subject_label`) or general. A missing or malformed classification writes nothing (`invalid`). A restored pending log passes through the same picker and is stored classified. Save is disabled until a category and a course are chosen. If saving fails (for example the database refuses a name with 23514) the session stays pending, the choices stay, and the student is told.
